# Исправление нативной грамматики review_answer

## Ошибка версии 3168e77

В [присланном фрагменте журнала](../evidence/review_grammar_failure_3168e77.txt) LANG-01 успешно загрузил данные, получил статистику и построил график. Затем нативный парсер llama.cpp отверг схему review_answer. Это ошибка введённой нами схемы, а не Kaggle или физических вычислений.

maxLength=4000 преобразовывался в повторение char{0,4000}. Предыдущие тесты проверяли Python-преобразователь JSON Schema → GBNF, который создаёт строку грамматики, но не доказывает, что её примет C++-парсер. Нативный парсер разворачивает ограниченные повторения; см. [официальную реализацию](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-grammar.cpp).

На локальной Windows-сборке llama-cpp-python 0.3.35 старая схема вызвала OSError: exception: stack overflow. В Kaggle пользователь получил exceeds sane defaults. Это разные реакции сборок на слишком большое повторение; точное сообщение Linux-сборки локально не воспроизведено.

## Минимальное исправление

Из грамматики удалены два ограничения maxLength для свободного текста. **Программные ограничения 4000 символов итогового текста и 180 символов отдельной оставшейся задачи сохранены**, равно как пределы массивов, типы, допустимые идентификаторы, проверка ссылок на доказательства и запрет отменять явные требования.

Ограничения 900 выходных токенов и 8000 входных символов со схемой не изменены. Основной системный промпт, мини-планировщик, класс модели, обработчики инструментов, математика и архиватор не менялись относительно 3168e77. Нативные библиотеки не обновлялись, лимиты самого llama.cpp не ослаблялись.

## Что теперь проверяется

Новый tools/check_review_grammar.py преобразует схему и вызывает **llama_sampler_init_grammar**, затем освобождает sampler. Инициализация каждой грамматики происходит в отдельном дочернем процессе. Модель и веса не загружаются, генерация и скачивание данных не выполняются. Проверяются варианты с 0, 1 и 8 дополнительными операциями.

Для обычного JSON на основе символьных правил проверяется только инициализация грамматики; словарь модели используется при семплировании, которое этот тест не выполняет. Следовательно, PASS нативного парсера не доказывает качество или научную правильность ответа Qwen.

Историческая схема сохранена в tests/fixtures/review_schema_3168e77.json. Опция --include-legacy отдельно воспроизводит её отказ. Обычная проверка перед приёмкой запускает только новые схемы.

Перед 16 сообщениями run_dual_stage_review.py автоматически выполняет нативную проверку. При отказе сообщения и обращения к источникам не начинаются. После завершения прогона отчёт включается в ZIP как native_review_grammar.json. Формулировки всех 16 сообщений и границы чатов сохранены.

## Результаты

**1439 passed, 0 failed, 0 skipped; 24 deselected.** Нативные проверки: **3/3 PASS** на Windows / llama-cpp-python 0.3.35. HTTP Gradio: **9/9 PASS**.

[Сводка проверок](../evidence/review_native_grammar_fix_20261128/RESULTS.json), [отчёт нативного парсера](../evidence/review_native_grammar_fix_20261128/native_grammar.json), [полный pytest-лог](../evidence/review_native_grammar_fix_20261128/pytest.txt), [JUnit](../evidence/review_native_grammar_fix_20261128/pytest.xml), [HTTP Gradio](../evidence/review_native_grammar_fix_20261128/gradio_http.json).

Добавлены 10 проверок: три варианта настоящего нативного парсера, сохранность старой схемы, границы 4000/4001 и 180/181, остановка до сообщений при плохой грамматике и сохранение отчёта в ZIP. Пропуск из-за отсутствия необязательной нативной библиотеки отмечается как SKIP, а не PASS.

Живая генерация Qwen после этого исправления и новая научная приёмка пока NOT_RUN. Предыдущие автономные результаты не переименованы в успешный живой прогон.

## Как запускать

Перезапустить kernel, выполнить свежую dev-ячейку 1 и подготовку до brain. Затем запустить прежнюю ячейку 16 сообщений из [описания итогового разбора](RESPONSE_REVIEW_FIX.md). В начале должны появиться три строки NATIVE review_answer: PASS; затем начинается неизменённый протокол.

Отдельно, после установки llama.cpp и до загрузки brain, можно выполнить:

```python
from pathlib import Path
import subprocess
import sys

subprocess.run(
    [sys.executable, "-B", str(Path(DIR) / "tools/check_review_grammar.py")],
    check=True,
)
```

Ожидается PASS для optional=0, optional=1 и optional=8 и путь к report.json. Это короткая нативная проверка без весов. Полный протокол по-прежнему проверяет два критерия раздельно: понимание обычных запросов и научные выводы.
