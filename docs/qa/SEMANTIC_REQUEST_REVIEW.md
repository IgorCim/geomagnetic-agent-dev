# Понимание естественных запросов и проверка мини планировщика

Изменения выполнены в копии `geomagnetic-agent-dev`, ветка `codex/semantic-request-planner`. Они устраняют зависимость выбора инструментов только от ключевых слов и сохраняют принадлежность численных результатов. Локальные проверки инфраструктуры прошли; научные ответы настоящей Qwen 14B требуют отдельного живого прогона.

## Что изменено

1. Отдельный внутренний инструмент `plan_request` в `request_planner.py` получает текущий запрос и короткие подтверждённые факты сессии **до выбора исполнительных инструментов**. Он возвращает режим работы, операции, метрики, станции и даты. Длинные рассуждения от модели не запрашиваются.
2. Код проверяет решение и добавляет зависимости выбранных операций. Например, для опорного уровня доступны наземная загрузка и производные компоненты, для LT — координаты. Доступность зависимости не обязывает повторно загружать данные; запреты пользователя сохраняются.
3. `GIC`, `SSC`, `SML`, `SME`, `SMU` и системы времени/координат отделены от станций. Цитируемое утверждение не превращается автоматически в задание на загрузку. Русские календарные даты нормализуются без угадывания года. Проверенные русские названия станций используются из существующего справочного текста агента.
4. Результат операции получает `input_provenance`: фактический handle, число строк, начало и конец покрытия в UTC. Статистика передаётся модели вместе с этой принадлежностью; раньше при сокращении большого сообщения численные поля могли исчезнуть. При сравнении отдельных дней нельзя использовать многосуточную таблицу как один день.

Режимы `explain` и `plan` не получают исполнительных инструментов. Режим `analyze` сохраняет содержательный ответ модели, вместо автоматической замены ответа перечнем фактов. При необходимости уточнения агент задаёт короткий вопрос. Большие задания выполняет прежний пакетный планировщик; мини планировщик сначала отличает предложение плана от команды на выполнение.

Основной `SYSTEM_PROMPT`, прежние 29 схем, пакетный `agent_planner.py`, математические функции и код построения графиков не изменены. GTsimulation и защищённый оригинал агента не редактировались.

## Ограничение нагрузки на модель

Мини планировщик делает не более одного отдельного вызова за сообщение. Его системный текст занимает 2070 символов, схема одного инструмента — 1628 символов при стандартной JSON-сериализации. Полный вход этого этапа ограничен 8000 символами вместе со схемой; выход — 360 токенами. Подтверждённые факты сессии ограничены 1800 символами. Его каталог возможностей не переносится в исполнительный диалог.

Исполнитель получает исходный запрос, короткое проверенное решение и выбранные полные схемы с зависимостями. Численные результаты с принадлежностью ограничены 1600 символами на сообщение; сокращение явно отмечается, полный результат остаётся в журнале.

Некорректный или слишком большой план вызывает явный `fallback` к прежнему маршрутизатору. Журнал содержит `[REQUEST PLANNER]` с решением или причиной перехода. Для сравнения со старой маршрутизацией можно установить `GEOMAG_REQUEST_PLANNER=0`; по умолчанию этап включён для `LlamaBrain`. Существующие тестовые модели без поддержки этого протокола сохраняют прежнюю последовательность ответов.

Это **команды терминала**, а не Python-код ячейки:

```text

В Python-ячейке Colab/Kaggle используй `subprocess`, указав каталог загруженного агента явно:

from pathlib import Path
import subprocess

import agent_core as ac

qa_root = Path(ac.__file__).resolve().parent

    [sys.executable, '-B', str(qa_root / 'tools' / 'verify_offline.py')],
    cwd=qa_root, check=True,

subprocess.run(
    [sys.executable, '-B', str(qa_root / 'tools' / 'verify_gradio.py'), '--port', '17861'],
    cwd=qa_root, check=True,

```

Это дополнительные автономные и HTTP-проверки; они не запускают 12 научных запросов. Для этих запросов нужна отдельная ячейка ниже.

Автономный набор выполняется в одноразовой копии; пользовательские результаты не используются как тестовые артефакты. При занятом порту HTTP-проверки выбери другой порт, не останавливая чужой сервер.

## Как провести живую проверку в Colab или Kaggle

В первой установочной ячейке выбери:

```python
REPO_URL = 'https://github.com/IgorCim/geomagnetic-agent-dev.git'
BRANCH = 'codex/semantic-request-planner'
```

Нужен чистый сеанс и обычные ячейки подготовки и загрузки `brain` из этой dev-ветки. Обновлять файлы после загрузки модели нельзя: это смешивает версии модулей. Затем выполни:

```python
from pathlib import Path
import runpy
import agent_core as ac

qa_root = Path(ac.__file__).resolve().parent
qa_script = qa_root / 'tools' / 'run_request_planner_review.py'
print('Загруженный агент:', qa_root, flush=True)
assert qa_script.is_file(), (
    f'В этом checkout нет {qa_script.name}. '
    'Нужен geomagnetic-agent-dev, ветка codex/semantic-request-planner. '
    'Выполни настройку первой ячейки ниже; поверх загруженного brain файлы не обновляй.'
)
assert 'brain' in globals() and isinstance(brain, ac.LlamaBrain), 'Сначала загрузи brain из этой dev-ветки.'
assert getattr(brain, 'supports_request_planning', False), (
    'Загружена старая версия brain. Нужен перезапуск kernel и подготовка из dev-ветки.'
)
for name in ('demo', 'qa_download'):
    ui = globals().get(name)
    if ui is not None:
        ui.close()
runner = runpy.run_path(str(qa_script))
qa_result = runner['run'](brain)
print('Результаты:', qa_result['run_dir'], flush=True)
print('ZIP доказательств:', qa_result['archive'], flush=True)
```

### Если возник FileNotFoundError

Сначала запусти исправленную ячейку выше: она собирает имя файла без обратного слеша перед `.py` и проверяет файл до закрытия Gradio. Если файл найден и `brain` поддерживает мини планировщик, перезапуск не нужен.

Если проверка сообщает, что файла нет, загружен checkout без нового runner. Файл добавлен в dev-ветку коммитом `8c67cc0`; загрузка оригинального репозитория или `master` не выбирает эту ветку автоматически.

1. Сохрани нужные выводы ноутбука. Перезапусти **kernel / сеанс Python**, сохраняя файлы рабочей среды; не удаляй результаты, checkout или веса.
2. В первой установочной ячейке замени **оба** параметра: `REPO_URL` на `https://github.com/IgorCim/geomagnetic-agent-dev.git`, `BRANCH` на `codex/semantic-request-planner`.
3. Выполни ячейку 1, затем прежние ячейки установки и загрузки `brain`. Не запускай старую первую ячейку следом: она снова выберет другой checkout.
4. Запусти ячейку научной проверки выше.

Не нужно отдельно скачивать только runner в старый каталог: проверяется новая связка мини планировщика и исполнителя, поэтому её модули должны происходить из одного checkout. Если в первой ячейке есть список `PROJECT_MODULES`, включи туда также `chat_session` и `request_planner` для защиты от смешивания версий при повторном запуске.

Запускаются 12 исходных сообщений: десять различных запросов и два повторных запроса из пользовательской выгрузки. Формулировки не исправлены. Запросы сохранены в [каталоге](SCIENTIFIC_ADVISOR_CASES.json), прежние ответы — в [исторической выгрузке](../evidence/scientific_advisor_before.txt). Исторические ошибки в этом файле не являются новыми результатами.

Границы девяти чатов заданы явно: утверждение о местной ночи идёт после задачи об опорных уровнях; просьбы усилить вывод идут после исследования гипотезы. Остальные задачи начинаются в новых чатах. Историческая выгрузка не содержит надёжных идентификаторов чатов, поэтому это контрольный повтор исходных формулировок с указанными границами, а не восстановление неизвестного состояния прежних сеансов.

В выводе видны запрос, `[REQUEST PLANNER]`, `[TOOL SELECTION]`, вызовы и окончательный ответ. В `turn.json` сохраняются результаты исполнения, а в CSV — использованные таблицы. Статус `HANDLER_RETURNED` означает возвращённый ответ, не научный PASS; окончательный вердикт остаётся `REVIEW_REQUIRED`.

## Как оценивать окончательные ответы

- Предложение плана не загружает данные и не строит графики. Станция BOU не должна называться Борком.
- Сравнение 10 и 12 сентября использует две отдельные суточные выборки. Числа в ответе должны соответствовать handle, покрытию и CSV своего дня; 72 строки не подменяют 24 часа одного дня.
- Отсутствие выбросов 3 сигма не доказывает отсутствие бури. Большое абсолютное H не доказывает более сильное возмущение на другой станции.
- Два опорных уровня действительно рассчитаны для одной таблицы разными способами; сравнение методов не требует графика, если пользователь его не просил.
- Проверка местной ночи использует координаты и местное солнечное время, с объяснением ограничений; UTC само по себе не определяет ночь.
- Редактирование научного абзаца не загружает выдуманную станцию GIC. Производная H не выдаётся за ток в амперах, совпадение рядов — за доказанную причинность.
- Объяснение уже полученного результата не запускает заново прежнюю цепочку. Просьба убрать неопределённость не должна создавать необоснованную уверенность.

После оценки этих ответов нужно повторить прежний `tools/run_full_evidence.py`: 29 инструментов, 20 реплик контекста, формулы, дополнительные серии и стресс. Старые формулировки и ранее сохранённые доказательства не заменены новым прогоном. Успех локальной инфраструктуры не засчитывает эти живые проверки заранее.
