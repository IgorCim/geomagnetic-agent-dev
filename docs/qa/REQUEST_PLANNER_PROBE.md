# Диагностика отклонения мини плана

Первый живой прогон `113a719` обработал 12 сообщений, но во всех случаях мини план был отклонён с `invalid_plan:ValueError`. В журнале нет исходного ответа планировщика и конкретного нарушенного правила. Поэтому формат ответа, обрезку по лимиту и семантическую валидацию пока нельзя различить. [Исходный журнал](../evidence/semantic_request_planner_live_20261125.txt), [оценка](../evidence/semantic_request_planner_live_20261125.json).

`tools/probe_request_planner.py` выполняет три исходных запроса: план исследования, два опорных уровня, критика научного абзаца. Для каждого создаётся пустая сессия, а модель вызывается ровно через существующие `understand_request` и `LlamaBrain.chat`. Декоратор передаёт параметры в тот же загруженный backend без изменений, сохраняет запрос, полный ответ backend, `finish_reason`, `usage`, результат разбора и точное сообщение валидации. Правила валидации не ослабляются, ответ модели не исправляется диагностикой.

Данные не скачиваются, научные инструменты не исполняются, веса не загружаются заново. Исходный `brain`, его настройки и файлы агента не подменяются. Обычное состояние контекста внутри backend меняется, как при любом новом обращении к модели. Диагностика использует отдельный адаптер вокруг того же backend; параллельные запросы к модели во время запуска недопустимы.

Скрипт совместим с уже загруженной версией `113a719`. Новый запуск всего ноутбука и обновление загруженных модулей не нужны. В свежем checkout, где файл уже есть, запуск:

```python
from pathlib import Path
import runpy
import agent_core as ac

qa_root = Path(ac.__file__).resolve().parent
probe = runpy.run_path(str(qa_root / 'tools' / 'probe_request_planner.py'))
probe_result = probe['run'](brain)
print('ZIP диагностики:', probe_result['archive'], flush=True)
```

Для текущего старого checkout скрипт можно загрузить отдельно с проверкой SHA256 и исполнить в отдельном словаре имён. Установщик и модули агента при этом повторно не запускаются. Готовая ячейка для существующего kernel (Kaggle и Colab):

```python
# Короткая диагностика; запускать с уже загруженным brain.
import hashlib
from urllib.request import urlopen

assert 'brain' in globals(), 'Сначала загрузи brain обычной ячейкой загрузки модели.'
probe_url = 'https://raw.githubusercontent.com/IgorCim/geomagnetic-agent-dev/3138ef07abaabf21bac7b5ab3ec7ce10c2c0c107/tools/probe_request_planner.py'
with urlopen(probe_url, timeout=30) as response:
    probe_code = response.read()
assert hashlib.sha256(probe_code).hexdigest() == '2f006dcf0b08ae460fa41e79445e894ababadd60ad1bf5c0c51dc9c3b4b13a11', 'SHA256 диагностики не совпал.'

probe_ns = {'__name__': 'request_planner_probe', '__file__': probe_url}
exec(compile(probe_code, probe_url, 'exec'), probe_ns)
for name in ('demo', 'qa_download'):
    ui = globals().get(name)
    if ui is not None:
        ui.close()
probe_result = probe_ns['run'](brain)
print('ZIP диагностики:', probe_result['archive'], flush=True)
```

Результаты `report.json` и `console.log` сохраняются сразу после каждого случая; в конце создаётся ZIP. Логин SuperMAG из окружения скрывается тем же средством, что и в существующей приёмке. `accepted` означает только успешный разбор и валидацию мини плана. Диагностика не оценивает научные выводы.

Проверены нативные вызовы, текстовые теги и JSON-оболочки, отсутствие вызова, голый объект решения, обрезанный JSON, чужой инструмент, ошибки backend и пять причин отклонения валидации. Полный цикл из трёх случаев проверен с явно обозначенным тестовым backend: подтверждены отсутствие научных вызовов, сохранение исходников, параметров и backend, а также редактирование секретов. Это не подмена живой проверки Qwen.

Автономный набор: **1295 passed, 23 deselected**, включая 16 новых тестов диагностики. [Журнал](../evidence/request_planner_probe_checks_20261126/pytest.txt), [метаданные](../evidence/request_planner_probe_checks_20261126/run.json).

После получения живой диагностики исправляется установленная причина. Затем повторяются исходные запросы без переформулировки, проверяются принятые планы и окончательные ответы; только после этого имеет смысл повторять полную научную приёмку. Исходный журнал не заменяется успешным повтором.
