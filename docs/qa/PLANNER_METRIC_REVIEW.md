# Проверка выбора физических метрик

## Что показал реальный прогон

[Исходный журнал Qwen](../evidence/request_planner_probe_v2_20261126.txt) сохранился целиком. Три JSON-решения приняты, режимы plan/analyze/explain выбраны верно. Но прежний критерий 3/3 проверял наличие calculate_baseline, не отсутствие лишнего физического расчёта.

| Исходный запрос | Формат | Проверка смысла маршрута |
| --- | --- | --- |
| Предложить исследование без загрузок | Принят | Пройдено: только обсуждение |
| Два опорных уровня H одной станции за один день | Принят | Не пройдено: добавлен не запрошенный eej_index и его оператор |
| Критика научного абзаца | Принят | Пройдено: только обсуждение |

Итак, **3/3 по протоколу, 2/3 по проверенным требованиям к маршрутам**. В этом запуске научных ответов вообще не генерировали. Верность будущего плана исследования и научной критики этим не подтверждается. [Повторная оценка записанного ответа](../evidence/planner_metric_review_20261126/recorded_review.json).

## Что изменено

Ранее идентификаторы физических метрик перечислялись в JSON Schema без объяснения их назначения в сообщении модели. Грамматика ограничивала допустимые написания; этого недостаточно для выбора физического смысла. Отдельный планировщик теперь получает короткое значение каждой из 11 метрик и явное указание оставлять metrics пустым, когда нужны обычные инструменты. Это общая информация о возможностях, без исключения для конкретного запроса или списка его формулировок.

Результаты модели не исправляются задним числом: EEJ не удаляется скрытым фильтром. Усиленная диагностика должна отклонить неверный маршрут, если модель снова его предложит. Для исходного сравнения уровней проверяются также станция, дата, нужный инструмент и отсутствие посторонних операций.

Основной системный промпт агента, его 29 схем, исполнение, физические функции, графики и пакетный планировщик не изменены. Нужен один вызов той же модели. Системный текст только этапа планирования вырос с 2295 до 2977 символов; пределы остаются 8000 входных символов со схемой и 360 выходных токенов. Новые запросы и отдельная модель не добавлены.

## Что проверено

**1332 passed, 24 deselected** в полном автономном наборе с блокировкой внешней сети. Семь новых проверок включают реальный ответ с лишним EEJ: протокол проходит, смысловой контроль выявляет ошибку. Также проверяется, что модель действительно получает описания всех метрик, исходные запросы не заменяются кратким пересказом, а прежний бюджет соблюдён. [Лог pytest](../evidence/planner_metric_review_20261126/pytest.txt), [метаданные](../evidence/planner_metric_review_20261126/run.json), [сводка](../evidence/planner_metric_review_20261126/RESULTS.json).

Это тесты кода и записанных ответов, не доказательство нового поведения Qwen. Живая проверка исправленного выбора метрик и полные 12 научных сообщений ещё нужны. Предыдущие 9 HTTP-проверок Gradio относятся к прежнему запуску; в этом изменении UI не затрагивался.

## Как продолжить

Сначала повторить тот же предпросмотр трёх исходных запросов с обновлённым компонентом. Установленный brain и файлы checkout не заменяются, kernel перезапускать не требуется. Ячейка сохраняет сырой ответ, параметры запроса, причины отклонения и ZIP. Раздельно выводятся принятие JSON и смысловая проверка маршрутов.

Если маршруты проходят, полные 12 исходных сообщений выполняются после нового checkout dev-ветки в свежем kernel. Только полный прогон покажет качество конечных расчётов и научных ответов. Формулировки из SCIENTIFIC_ADVISOR_CASES.json сохранены.

[Текущая ячейка предпросмотра](https://github.com/IgorCim/geomagnetic-agent-dev/blob/codex/semantic-request-planner/tools/kaggle_preview_structured_planner.py) использует компонент и наблюдатель из неизменяемого коммита `ad624a0cc0f816039e7c192d3bec200166bcf0e0` с проверкой SHA256 обоих файлов.
