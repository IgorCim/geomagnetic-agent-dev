## Подтверждённая ошибка baseline

В ADVISOR-10 уровень 18265.270791634288 рассчитан для raw:irt:2024-09-12. Модель затем передала это точное значение для derived:irt:2024-09-12. Прежняя проверка сопоставляла только имена слотов и отвергала корректный переход.

Теперь уровень привязан к содержимому компоненты и UTC-оси в момент расчёта. Сопоставление учитывает станцию, дату, компоненту, все значения и временные метки. Эквивалентный derived допустим. Другая станция, дата, изменённый ряд, другая временная ось, придуманный уровень и повторно использованный слот с новым содержимым не допускаются. Никакого допуска для округлённого или приблизительного baseline не добавлено.

Формулы расчётов остаются прежними. Слово Quiet в сообщении инструмента заменено обозначением Reference: выполнение среднего по UTC-окну само по себе не доказывает спокойствие и локальную ночь.

## Отдельный итоговый этап

Добавлен response_review.py. После завершения работы инструментов выполняется один отдельный вызов той же загруженной модели. В нём нет схем исполнения, обработчиков инструментов и истории ответов помощника. Передаются полный текущий вопрос, подтверждённые результаты, фактический перечень таблиц с числом строк и UTC-покрытием, справочные определения и реальные имена файлов ZIP.

Этот этап определяет, нужны ли числа, объяснение или методический план, заново по полному вопросу. Поэтому ошибочная классификация facts в первом плане больше не является единственным основанием для удаления объяснения. Числовой ответ формируется прежним кодом фактов. Объяснение сопровождается подтверждёнными результатами; исходный черновик сохраняется отдельно в доказательствах.

Есть строго ограниченная возможность отметить лишний предложенный способ работы: например, ненужный SuperMAG при уже полученной статистике наблюдений. Нельзя отменить прямо названный инструмент или источник, обязательную физическую метрику, статистику или фактически отсутствующую таблицу. Для альтернативы требуются ссылки на записанные вычисления, а не только на факт скачивания. Оставшиеся обязательства заново проверяет код. Некорректный JSON или ошибка этапа не превращаются в успешный ответ.

Планировщик получает более короткое описание задачи: отличать конечный результат от вспомогательного способа, выбирать минимальные операции и различать абсолютные наблюдения INTERMAGNET и возмущения SuperMAG. Наличие логина передаётся булевым признаком конкретной сессии; значение в модель и журнал не передаётся.

## Как повторить живую проверку

Перезапустить kernel. Выполнить dev-ячейку 1, затем обычную подготовку и загрузку brain. После загрузки не обновлять файлы. Используется тот же протокол: 4 контроля + 12 первоначальных научных сообщений в 12 чатах.

```python
from pathlib import Path
import runpy
import agent_core as ac

assert isinstance(globals().get("brain"), ac.LlamaBrain), "Сначала загрузи brain."
qa_root = Path(ac.__file__).resolve().parent
assert globals().get("DIR") and qa_root == Path(DIR).resolve(), "Другой checkout."
assert (qa_root / "response_review.py").is_file(), "Нужен свежий dev-checkout."
assert "response_review" in ac.run_agent.__code__.co_names, "Нужен новый kernel и свежая dev-версия."

for name in ("demo", "qa_download"):
    ui = globals().get(name)
    if ui is not None:
        ui.close()

print("Версия:", ac.code_revision(), flush=True)
runner = runpy.run_path(str(qa_root / "tools/run_dual_stage_review.py"))
qa_result = runner["run"](brain)
print("Результаты:", qa_result["run_dir"], flush=True)
print("ZIP доказательств:", qa_result["archive"], flush=True)
```

В консоли появятся отдельно plan_request, выполнение инструментов и review_answer. В архиве сохраняются исходный план, черновик, вход итогового этапа, его ответ, конечный текст, результаты инструментов и CSV. Научная оценка остаётся REVIEW_REQUIRED, даже если все четыре контроля действий пройдут.
