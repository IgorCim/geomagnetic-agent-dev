# Исправление выбора действий после прогона 1e716a1

## Фактический результат присланного прогона

[Полный неизменённый журнал](../evidence/dual_review_1e716a1_20261127.txt) и [сводка](../evidence/work_selection_fix_20261127/previous_live_review.json) сохранены.

Автоматический контроль действий дал **1/4**. Успешный контроль относится к отсутствию исполнения при разборе текста; сам текст содержит научную ошибку, поэтому это не научный PASS. Три новых разговорных задания не выполнены. Планировщик принял 6 решений из 16 и отклонил 10: девять из-за противоречия required со списками tools/metrics, ещё одно — из-за выдуманной даты 2023-01-01.

В LANG-01 модель выбрала подходящие get_statistics и plot_components, но назвала обязательные результаты min/max/median/plot. Код требовал идентификаторы операций и отклонил ответ. Это дефект введённого интерфейса: форма required допускала произвольные строки, а валидатор требовал другую семантику. Такой отказ нельзя целиком приписывать непониманию разговорной речи.

Научные проблемы остаются: H назван вертикальным в SCI-X01; в ADVISOR-09 сохранён вывод от отсутствия выбросов к отсутствию бури. Продолжения после заблокированной загрузки не проверяют рассуждение по успешно полученным наблюдениям. Исправления справки и инструкций не считаются доказательством исправления настоящего ответа модели.

## Что изменено в интерфейсе

Три связанных массива заменены **одним списком work**. У каждой записи два поля:

```json
{"id":"get_statistics","required":true}
```

Идентификатор выбирается из перечисления всех зарегистрированных инструментов и физических операций; required имеет тип boolean. На уровне JSON-грамматики нельзя выдать произвольный min_h или baseline_full_day вместо операции. Обязательность относится к тому же идентификатору, поэтому нет второй независимой таблицы имён для сопоставления. Код не угадывает псевдонимы и не преобразует формулировки конкретных тестов в действия.

До восьми записей описывают виды операций, а не все будущие вызовы. Параметры, число результатов, станции и окна остаются в полном исходном запросе исполнителю. Повтор одного вида операции не стирает его обязательность. Данные старого интерфейса сохраняются для исторических журналов и старых адаптеров; современный production-вызов их не принимает скрытым fallback.

Канонические tools/metrics/required_operations вычисляются кодом из единственного выбора. Разделение обязательной работы и вспомогательных возможностей сохраняется. Необходимые зависимости добавляются прежним механизмом.

## Контекст и научное объяснение

Явно заданные пользователем даты, станции и handle сохраняются отдельно от фактически полученных данных. Поэтому отказ запроса не стирает заданный пользователем год в следующей реплике. В контекст не попадает произвольный текст запроса или логин; список целей ограничен двумя записями и помечен как не являющийся наблюдениями. Пустая таблица не становится загруженной только из-за сохранённой цели. Обозначения GIC/SML/EEJ/IMF не становятся станциями.

Справка уточняет H как горизонтальную величину hypot(X,Y), Z — вертикальную. При объяснении модель получает указание различать подтверждённое, гипотезы и то, что из данных не следует, и сохранять эти различия в исправленном тексте. Это общие определения и способ работы с утверждениями, а не заготовленный ответ на конкретный вопрос.

Исправления двух опорных уровней и перечней дат сохранены. Основной SYSTEM_PROMPT, 29 схем, LlamaBrain и его параметры, физическая математика, графики и пакетный планировщик не изменены. Планировщик остаётся одним вызовом с 360 выходными токенами и 8000 входными символами со схемой; его системный текст — 3093 символа.

## Как повторить

Полный протокол остаётся тем же: 4 новых контроля плюс все 12 исходных научных сообщений с прежними формулировками и границами чатов. Скрипт — tools/run_dual_stage_review.py. Тест проверяет равенство первоначальному плану.

Нужен свежий kernel: dev-ячейка 1 с geomagnetic-agent-dev/codex/semantic-request-planner, затем обычные 2–5. Тестовую ячейку заменить: старое условие о поле required относится к предыдущей версии.

```python
from pathlib import Path
import runpy
import agent_core as ac
import request_planner as rp

assert isinstance(globals().get("brain"), ac.LlamaBrain), "Сначала загрузи brain."
assert "work" in rp.ARGUMENT_SCHEMA["properties"], "Нужен свежий dev-checkout."
qa_root = Path(ac.__file__).resolve().parent
assert globals().get("DIR") and qa_root == Path(DIR).resolve(), "Другой checkout."
for name in ("demo", "qa_download"):
    ui = globals().get(name)
    if ui is not None:
        ui.close()
print("Версия:", ac.code_revision(), flush=True)
runner = runpy.run_path(str(qa_root / "tools/run_dual_stage_review.py"))
qa_result = runner["run"](brain)
print("Результаты:", qa_result["run_dir"], flush=True)
print("ZIP доказательств:", qa_result["archive"], flush=True)
```

Контроль действий и научная оценка остаются раздельными. Ни 1381 автономная проверка, ни принимаемый JSON не являются доказательством общей языковой или научной компетентности модели.
